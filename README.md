# Digsight

**把一个需要查证的问题，做成一份能追溯来源的调研报告。**

Digsight 是一个运行在本机的调研工作台。输入一个问题，它会拆出决定答案的子问题，让 DeepSeek 和 WorkBuddy 分头查找公开资料，再把原始回答、来源、分歧和证据缺口整理成一份报告。你可以先读结论，再顺着出处回看依据。

## 适合拿来查什么

- **做工具选型。** 一个 5 人团队该选哪款 AI 编程工具？分别核对费用、代码和提示词的留存政策、管理员能控制的功能。
- **判断行业进展。** 人形机器人在哪些工厂开始落地？把产品发布、试点、付费订单和正式部署分开看。
- **查证一条流传的说法。** 找到最初的公告、财报或论文，核对日期、样本和统计口径，再看其他报道是否都引用了同一份材料。

## 一次调研会得到什么

1. **一组可分头核实的问题。** 综合模型按证据需要拆题，也可以手动指定题数。每道子题有明确的检索任务。
2. **各引擎的原始材料。** 每题使用独立网页会话，保留回答和来源。可只选一个引擎起步；同时选择两个时，可以对照各自找到的材料。
3. **可追溯的判断。** 逐题对照证据，区分两边引用同一原文的情况，列出冲突、反例和仍待查证的部分。可选的引用核查会记录公开网页的可访问性与正文摘录。
4. **一份可导出的报告。** 在本地界面阅读或下载 Markdown，也可打开独立 HTML 报告并用浏览器打印为 PDF。原始材料、核查记录和运行过程仍可从对应调研中查看。

## 快速开始

准备以下环境：

- **Node.js 23.6 或更高版本**，本版在 Node.js 24 上验证。
- **[Ego Lite](https://lite.ego.app/)**。完成安装和首次引导，确认终端能运行 `ego-browser --version`。在 Ego Lite 中登录要使用的 [DeepSeek](https://chat.deepseek.com/) 或 [WorkBuddy](https://www.workbuddy.cn/app)。
- **一个有权使用的综合模型。** Digsight 通过 pi SDK 使用你本机的授权。已有 pi 授权可以直接使用。安装项目依赖后，首次配置可执行 `npm run setup`，在 pi 中用 `/login` 添加自己的 API Key 或登录受支持的订阅，然后用 `/model` 选择默认模型并按 Ctrl+S 保存。

```bash
git clone https://github.com/AyingAI/digsight.git
cd digsight
npm ci --ignore-scripts
npm start
```

打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)。新安装的历史列表为空。可以点一个示例填入问题，再根据需要选择引擎，点击「开始调研」。网页账号和综合模型授权独立，费用和额度由对应的服务提供商决定。

如果首页提示缺少环境，点击「运行环境」查看原因。也可以执行 `npm run doctor`，它会打开第三方网站检查登录和页面状态。调研时请让 Ego Lite 保持运行，遇到登录或验证码时可在打开的页面处理。

### 命令行

```bash
npm run run -- "人形机器人在哪些工厂已有付费部署？请区分试点和正式订单。" \
  --engines deepseek --subquestions 3 --concurrency 2
```

- `npm run run -- --help` 查看模型、超时、核查上限、输出目录等参数。
- `npm run rebuild -- RUN_ID` 根据一次运行留下的材料重新生成报告，把 `RUN_ID` 替换成 `runs/` 下对应的目录名。
- `DIGSIGHT_PORT=4318 npm start` 在默认端口已被占用时启动。

## 数据和隐私

- **调研会请求第三方服务。** 原始问题发给所选综合模型，调研任务书发给你启用的网页引擎，采集回答和引用摘录会返回给综合模型分析。请提交有权交给这些服务处理的内容。
- **授权由你管理。** 网页登录保存在 Ego Lite 的浏览器会话，综合模型凭据由 pi 管理。公开源码和发布包只提供程序、文档和测试。
- **调研记录保存在本机。** 默认目录为 `./runs/`，可用 `DIGSIGHT_RUNS_DIR` 指向其他位置。记录包含问题、提示词、回答、会话链接、日志和报告。历史列表中的移除操作只隐藏条目。需要彻底清理时，退出应用后删除对应运行目录。分享报告前请检查其内容和链接。
- **原始 HTML 和失败截图默认关闭。** 只有排查问题时才建议开启 `DIGSIGHT_SAVE_RAW_HTML=1` 或 `DIGSIGHT_SAVE_SCREENSHOTS=1`。这些文件可能含页面上的私人信息。
- **本机单用户使用。** 服务默认仅监听环回地址。本机进程可访问它，请避免通过反向代理、隧道或端口转发公开。

## 当前边界

- 引用核查请求只读取公开静态 HTML 或文本。需要登录、执行 JavaScript、返回 PDF，或被网络代理解析到保留地址的链接，可能无法核查。网页可访问性只是核查的一部分，重要事实应回到原始资料确认。
- 网页调研依赖第三方的登录状态、配额和页面结构。页面变更时，适配器可能需要更新。取消本地运行后，已经被第三方接收的任务仍可能继续执行。
- 每个服务实例一次运行一项调研。历史记录用于回看和重建报告，重新调研会创建新记录。

## 开发

```bash
npm run check
```

这会执行 TypeScript 检查、前端语法检查和回归测试。测试使用临时目录及模拟依赖，HTTP 用例需要本机环回端口。

`src/pipeline.ts` 编排调研，`src/browser/ego.ts` 适配网页引擎，`src/citations.ts` 核查公开引用，`src/report/` 生成报告，`web/` 提供本地界面。[调研报告写作约定](docs/research-report-writing.md)记录了报告组织方式。
